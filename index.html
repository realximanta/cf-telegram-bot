Overview

Cloudflare's dashboard is great on a laptop and painful on a phone — especially on prepaid data. This bot replaces the whole workflow with a Telegram conversation. You type /cname, choose a domain, send the target, and pick a proxy setting. You can also run /list to browse records, flip the orange cloud on any proxiable record, or delete records with a two-step confirmation.

The project is open source under the MIT license, ships with a render.yaml for one-click deploys, and exposes a /health endpoint so a free UptimeRobot monitor keeps it awake around the clock.

Features

Data-cheap by design

Telegram text commands cost under 1 KB. The Cloudflare dashboard loads 2–5 MB per visit.

Locked to you

Only chat IDs listed in ALLOWED_CHAT_IDS get a response. Everyone else is ignored.

Complete DNS control

Create CNAMEs, browse paginated record lists, toggle the orange cloud, and safely delete records with confirmation.

Self keep-alive

Ships a /health endpoint that Render and UptimeRobot use to keep the service hot 24/7.

Extensible

Adding /a, /txt, /mx, and more is a matter of one handler each.

Zero cost

Render free tier plus UptimeRobot free tier — the whole stack runs at $0 per month.

Flow

A full DNS change, start to finish, from Telegram.

telegram — @your_cf_bot 
You   /cname
Bot   Step 1/4 — Send the subdomain name you want to create.
       Example: mysub

You   mysub
Bot   Step 2/4 — Pick the domain for mysub:
       [ mysub.example.com ]   [ mysub.example.net ]
       [ mysub.example.org ]   [ Cancel ]

You   ( taps mysub.example.com )
Bot   Step 3/4 — Selected: mysub.example.com
       Now send the target hostname. Example: user.github.io

You   user.github.io
Bot   Step 4/4 — Proxy this record through Cloudflare?
       [ 🟠 Proxied — orange cloud ]
       [ ⚪ DNS only — grey cloud ]
       [ ❌ Cancel ]

You   ( taps ⚪ DNS only )
Bot   DNS record created successfully.
       Domain:  mysub.example.com
       Type:    CNAME
       Target:  user.github.io
       Proxied: No    TTL: Auto

Quick start

  1. Fork the repository. Open github.com/realximanta/cf-telegram-bot and click Fork.
  2. Create a Telegram bot. Message @BotFather, run /newbot, and copy the token.
  3. Get your Telegram ID. Message @userinfobot and copy the numeric ID.
  4. Create a Cloudflare API token. Go to Cloudflare API Tokens, use the Edit zone DNS template, keep Zone:Read and DNS:Edit, scope it to the zones you want.
  5. Deploy on Render. New → Blueprint → select your fork → fill the three env vars.
  6. Keep it alive. Add an UptimeRobot monitor on https://<your-service>.onrender.com/health, interval 5 minutes.

Deploy

Render reads the render.yaml Blueprint from your fork automatically. You only need to provide three environment variables.

# .env
TELEGRAM_TOKEN="123456789:AAYourTokenFromBotFather"
CF_API_TOKEN="your_cloudflare_api_token"
ALLOWED_CHAT_IDS="123456789"       # comma-separated
PORT=8080                            # Render injects this automatically

Once Render reports a healthy deploy you can message your bot on Telegram and run /start.

FAQ

Is this really free to run?

Yes. The code is MIT licensed, and the recommended stack — Render's free web service plus a free UptimeRobot monitor — costs nothing.

How much mobile data does it actually use?

A full DNS change over Telegram is under 1 KB round-trip. Opening the Cloudflare dashboard once is 2–5 MB of HTML, JS, and fonts.

Can somebody else use my bot if they find it?

No. The bot ignores every chat ID that isn't listed in ALLOWED_CHAT_IDS. Only you get a response.

What DNS operations are supported today?

Create CNAME records, browse zones with paginated record lists, toggle the Cloudflare proxy (orange cloud) on or off, and delete records with a confirmation step. A, AAAA, TXT, MX, and SRV creation are on the roadmap.

Why do I need UptimeRobot?

Render's free tier sleeps after roughly 15 minutes of inactivity. UptimeRobot pings the bot's /health endpoint every 5 minutes to keep it hot.
